# 前端概要设计（Frontend High-Level Design）

- **文档版本**：v1.0
- **对应需求**：`需求文档/AI智能周报系统需求文档V2.0 副本.docx`
- **影响模块**：`front`
- **更新日期**：2026-10

---

## 一、设计目标与原则

依据需求文档第五章（页面原型）、第七章（异常边界）与第十章（技术方案建议）实现一套面向**现场演示**的 Web 单页应用（SPA）。核心目标：

1. **演示导向**：主流程（登录 → 输入 → AI 生成 → 编辑 → 保存 → 查看）零说明可完成，空态 / 加载态 / 错误态齐全，绝不白屏。
2. **并行友好**：严格按 `material/design/api-spec-v1.md`（即需求 6.2 接口契约）对接，接口契约冻结后前端可 Mock 先行。
3. **降级可控**：AI 生成失败、超时、解析失败时，前端按 `GEN-06 / GEN-07` 切换降级模式，保证演示不中断。
4. **权限展示层控制**：前端仅做展示层隐藏（AUTH-01），真实越权拦截由后端返回 403 / 401 兜底。

## 二、技术选型建议

| 维度 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | React 18 + TypeScript | 生态成熟、组件化清晰，便于 5 页面快速搭建 |
| 构建 | Vite | 启动快、演示环境零配置 |
| 路由 | React Router v6 | 实现 5 个页面的路由与未登录跳转（LOGIN-03） |
| UI 组件库 | Ant Design 5（antd） | 内置表单、表格、卡片、消息提示，契合「周报列表 / 总览表 / 风险标签」等场景 |
| 请求 | Axios | 统一拦截 401/403/400/504/500，统一错误提示 |
| 状态管理 | Zustand（或 React Context + useReducer） | 仅存登录用户、token、当前周次等轻量全局态 |
| 剪贴板 / 下载 | 原生 `navigator.clipboard` / `Blob` | 团队周报复制与 .txt 导出（OVR-08） |

> 若团队对 Vue 更熟，可整体替换为 Vue3 + Element Plus，接口与状态划分一致。

## 三、系统架构

```
浏览器
  └── React SPA (Vite)
        ├── 路由层 (React Router)        —— 页面跳转 + 登录守卫
        ├── 状态层 (Zustand)             —— user / token / currentWeek
        ├── 请求层 (Axios + 拦截器)      —— 401跳登录 / 403提示 / 504重试+降级
        ├── 页面层 (Pages P1~P5)
        └── 公共组件层 (Components)
                 ├── Layout/TopNav       顶部导航 + 切换账号
                 ├── ReportEditor        四字段可编辑区（复用 P2/P3/P4 详情）
                 ├── RiskTag             风险 ⚠ 标签
                 ├── EmptyState          统一空态
                 └── AIGenerateButton    AI生成按钮（含加载/重试/降级）
```

**联调约定**：请求基地址通过 `.env` 配置（`VITE_API_BASE=/api` 或代理到后端）。开发期未联调前用 Mock 适配器替换 `services/*`，保证页面就绪。

## 四、页面与路由划分（对应需求第五章）

| 路由 | 页面 ID | 页面 | 可见角色 | 入口 |
| --- | --- | --- | --- | --- |
| `/login` | P1 | 登录页 | 所有人 | 未登录默认页 |
| `/report/edit` | P2 | 周报编辑页 | member | 成员首页 |
| `/my-reports` | P3 | 我的周报列表页 | member | 顶部导航「我的周报」 |
| `/team/reports` | P4 | 成员周报管理页 | leader | 负责人首页 |
| `/team/overview` | P5 | 团队总览页 | leader | 顶部导航「团队总览」 |

**路由守卫（LOGIN-03 / AUTH-03）**：
- 未携带有效 token 访问受保护路由 → 重定向 `/login`。
- 已登录但角色与页面不匹配（如 member 访问 P4/P5）→ 提示「无权限访问」并停留在自己首页（后端仍会返回 403 兜底）。

**顶部导航（TopNav，常驻）**：产品名 + 当前用户（姓名 + 角色标签）+「切换账号」（LOGIN-04，点击登出回登录页）。
- member 可见：`[P2 编辑]` `[P3 我的周报]`
- leader 可见：`[P4 成员管理]` `[P5 团队总览]`

## 五、模块 / 组件划分

### 5.1 公共组件
- `TopNav`：导航栏 + 当前用户 + 切换账号（LOGIN-04）。
- `ReportEditor`：**核心复用组件**，承载四字段编辑区（本周完成 / 进行中 / 问题与风险 / 下周计划），每条目多行文本框，逐字段独立编辑（GEN-08）。被 P2 新建、P3 详情回填、P4 负责人代编辑三处复用。
- `AIGenerateButton`：校验空输入（GEN-01 置灰）、加载态（GEN-04，文案「AI 正在整理你的周报…」，20s 超时）、失败重试（GEN-06）、连续 2 次失败后展示「切换为模板填写模式」降级入口（GEN-07）。
- `RiskTag`：⚠ 风险标签（OVR-01）。
- `EmptyState`：统一空态文案组件，禁止白屏。
- `ConfirmModal`：覆盖确认（GEN-05）、离开未保存确认（第七章）。

### 5.2 页面职责
- **P1 登录页**：4 个预置账号卡片（头像占位 + 姓名 + 角色标签），点击选中高亮（LOGIN-01）；登录按钮免密进入对应角色首页（LOGIN-02）。无空态/错误态。
- **P2 周报编辑页（成员核心）**：
  - 周次标题自动展示当前周（ISO 周 `YYYY-Www`）。
  - 输入区：标签「① 随手写下你本周做了什么」+ 多行文本框 + 占位提示（GEN-03）+ 字数计数（0/2000，超长截断 GEN-02）。
  - AI 生成按钮（见 5.1）。
  - 编辑区：标签「② 标准周报（可编辑）」+ 四字段文本框（AI 结果逐字段填充，GEN-05 覆盖确认）。
  - 操作栏：保存草稿（REP-01）/ 提交周报（状态 → submitted），离开未保存弹确认（第七章）。
  - 状态：加载态（编辑区禁用）；降级模式（隐藏 AI 按钮，仅保留手动填写）。
- **P3 我的周报列表页**：标题「我的周报」+「去写本周周报」按钮（跳 P2）+ 周报列表（列：周次 / 状态 / 本周完成摘要 / 更新时间，见 4.4）。点击行进入该周详情（复用 ReportEditor 回填）。空态：「还没有周报，点击上方按钮开始第一篇」。
- **P4 成员周报管理页（负责人首页）**：按成员分组（成员名 + 角色标签，组内按周次倒序，默认展开本周，LEAD-01/02），行展示 周次 / 状态 / 更新时间 / 最后编辑人。点击进入代编辑详情（复用 ReportEditor，顶部提示「正在查看：张成员 · 2026-W42」，LEAD-03）。某成员本周无周报显示「本周未开始」灰字占位行。
- **P5 团队总览页**：
  - 标题「团队周报总览 · 2026-W42」+ 刷新按钮（OVR-04，实时快照不轮询）。
  - 筛选栏：提交状态（全部 / 已提交 / 未提交，OVR-02）。
  - 总览列表（列：成员 / 提交状态 / 本周完成 / 进行中 / 风险 / 更新时间，见 4.6.1）：风险 ⚠ 点击展开条目（OVR-01）；本周完成超 3 条折叠 `+N`。
  - AI 汇总区：「生成团队周报」按钮（无任何周报时置灰提示「暂无可汇总的周报」，OVR-05）+ 四段结果展示 +「复制全文」「导出 .txt」（OVR-08，文件名 `团队周报_YYYY-Www.txt`）。
  - 状态：空态（OVR-03）；AI 加载/失败重试（OVR-07）；未生成时引导文案「点击上方按钮，AI帮你把全员周报汇总成团队周报」。

## 六、状态与边界场景实现（对应需求第七章）

| 场景 | 前端处理 | 依据 |
| --- | --- | --- |
| AI 输入为空 | 按钮置灰，禁止调用 | GEN-01 |
| 输入超 2000 字 | 计数提示并截断 | GEN-02 |
| AI 生成超时 (>20s) | 按钮加载态，超时提示「生成失败，请重试」+ 降级入口 | GEN-04/06 |
| JSON 解析失败 | 统一提示「生成失败，请重试」，禁止展示原始报错 | GEN-06、6.3 |
| 连续 2 次失败 | 额外展示「切换为模板填写模式」 | GEN-07 |
| 总览全员未提交 | 展示空态文案，不渲染空表 | OVR-03 |
| 切换账号有未保存编辑 | 离开前弹「未保存的修改将丢失」 | 第七章 |
| 已提交周报被编辑 | 保存后状态回退草稿（后端返回，前端刷新状态） | REP-02 |
| 历史周次周报 | 复用编辑区，规则同本周 | 4.4/P3 |
| token 失效 / 缺失 | Axios 拦截 401 → 跳登录页 | AUTH-03 |
| 越权访问他人/总览 | Axios 拦截 403 → 提示「无权限访问」 | AUTH-02 |

## 七、接口对接清单（详细契约见 `api-spec-v1.md`）

前端 `services/` 封装以下调用（含统一错误码映射）：

| 前端方法 | 接口 | 权限 | 用途 |
| --- | --- | --- | --- |
| `login(userId)` | `POST /api/login` | 公开 | 免密登录拿 token |
| `getTemplate()` | `GET /api/template` | 登录 | 拉取四字段模板结构（TPL-01，前端不硬编码） |
| `getMyReports()` | `GET /api/reports/mine` | member/leader | 我的周报列表 |
| `createReport(payload)` | `POST /api/reports` | member | 新建本人周报 |
| `getReport(id)` / `updateReport(id, payload)` | `GET/PUT /api/reports/{id}` | 本人/leader | 详情/更新 |
| `getTeamReports(week)` | `GET /api/reports/team` | leader | 团队周报列表（含未开始标记） |
| `generateReport(input)` | `POST /api/reports/generate` | 登录 | AI 生成个人周报 |
| `generateTeamSummary(week)` | `POST /api/reports/team-summary` | leader | AI 汇总团队周报 |
| `exportTeamSummary(week)` | `GET /api/reports/team-summary/export` | leader | 导出 .txt |

**错误码统一处理（Axios 拦截器）**：
- `400` → 表单级错误提示；`401` → 清 token 跳登录；`403` → 「无权限访问」；`504` → 重试 + 降级入口；`500` → 「服务异常，请稍后重试」。
