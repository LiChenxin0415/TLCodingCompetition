# material — 项目资料

本目录存放本项目的**需求与设计类资料**（非代码交付物），是所有智能体开发前的**唯一事实来源**。

## 目录结构

```
material/
├── requirements/   # 业务需求（业需）：需求说明、用户故事、业务规则、验收标准
├── design/         # 概要设计（概设）：架构设计、模块划分、数据库设计、接口定义
├── ui/             # UI 设计：原型、设计稿、切图、设计规范
└── meeting/        # 会议纪要、评审记录、决策记录（ADR）
```

## 资料规范（协作要求）

1. **开工前先同步**：`git pull --rebase origin main`，并确认自己依赖的文档是**最新版本**再动手实现。
2. **文档格式**：一律使用 Markdown；图片放在同级 `assets/` 目录中并以相对路径引用。
3. **命名规范**：英文小写 + 中划线 + 版本，例如 `order-flow-v1.md`、`api-spec-v2.md`。
4. **变更即推送**：需求或设计一旦变更，**必须更新文档并立即 push**；不允许只口头同步。
5. **影响面标注**：接口、字段、流程变更需在文档头部与提交信息中注明影响模块（`front` / `back`）。
6. **版本留痕**：不要删除旧版本结论，改为追加「变更记录」章节，便于其他智能体判断时效性。
7. **不要提交**：超过 20MB 的原始设计源文件（如 PSD、视频），改放网盘链接并在此说明。

## 提交信息示例

```
[agent:ba][material] 补充业需 V0.3 订单流程
[agent:arch][material] 更新概设：订单模块数据库设计
```

## 文档模板

### 业务需求（`requirements/`）
- 背景与目标 / 用户角色 / 业务流程 / 功能点与优先级 / 验收标准 / 变更记录

### 概要设计（`design/`）
- 系统架构 / 模块划分 / 数据库设计（表结构、索引） / 接口定义（路径、入参、出参、错误码） / 变更记录

### UI 设计（`ui/`）
- 页面清单 / 交互说明 / 设计稿链接或图片 / 标注说明 / 变更记录
